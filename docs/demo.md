# Пятиминутное демо

1. 0:00–0:30 — задача аналитика: кого проверить первым среди 2248 синтетических клиентов.
2. 0:30–1:10 — выполнить `.venv/bin/python starter.py --data data --out out`, показать время и три файла. В уже запущенном `.venv/bin/python serve.py` открыть http://127.0.0.1:3000/network и нажать «Пересчитать» (на первом открытии «Запустить анализ»).
3. 1:10–2:10 — выбрать `100000003684369100` из очереди; в правом инспекторе «Обзор» раскрыть основания роли coordinator: достижимость от девяти seed, связи с другими кластерами, процентиль посредничества и направленные переводы. Показать «Связи».
4. 2:10–3:00 — найти `100000008165763100` как пример distributor; затем отфильтровать сеть по четвёртому колену, выбрать любой узел и объяснить границу наблюдения по его карточке.
5. 3:00–3:50 — найти gid, который назовут проверяющие; показать карточку, контрагентов и направление денег.
6. 3:50–4:30 — открыть «Переводы», затем «AI». При настроенном API нажать «Объяснить роль», затем спросить «Каких данных не хватает для проверки?». Ответ остаётся гипотезой; точные условия показаны отдельно. Без API или при задержке показать «Объяснение правил без LLM» и не ждать модель в ущерб обязательной части.
7. 4:30–5:00 — в «Отчётах» скачать три CSV одного run, показать manifest. В «Данные и методика» указать конфигурацию/ограничения. Напомнить, что схема находится в docs/architecture.md, а команда воспроизведения в README.

Примерные gid здесь только для репетиции; классификация их не использует. При изменении данных брать примеры из текущего результата.
